# Test Coverage Ledger

Inventory of every app, driver and integration in this repository and its current automated-test coverage. The bar for what qualifies as a test, and the meaning of each Mode number, is defined in [`TESTING.md`](TESTING.md). This file is the ledger; that file is the policy.

Table cells display source and artifact paths relative to the repository root. Test scripts, specs and snapshots appear only in the Test artifact column. Apps and drivers that tests install (fixtures and probes) have rows. Work in progress is not listed.

**Conventions used in the tables below**
- **Mode** values: `1` (behavior, the lead tier), `2` (API integration), `3` (pure-JS unit), `4` (Python mirror or Groovy extraction), `5` (in-hub stress, exempt from section 1.1). `—` means no automated test. `(via parent)` marks a component child exercised only through its parent's tests. `(fixture)` marks a test-only driver.
- **Required?** column reflects the tiered bar in [`TESTING.md`](TESTING.md) section 2.2.
  - `Y`: tier requires a test for new or significantly-changed code.
  - `N`: no test required by the bar, but one would still be useful.
  - `exempt`: Mode 5 stress apps, probes, fixtures, parent shells, component children and files that are not independently invocable.
- **Test artifact** is the canonical entry point (the `.sh`, `.js`, `.py` or `.groovy` file that runs the test).
- Scripts marked `TEST-LIVE` in their header need a reachable hub; the Mode 4 extraction tests and `.js` tests run off the hub.

When you ship a new test, add or update its row here in the same commit as the test artifact.
